Die Desktop-App ist jetzt **klein**: Tauri statt Electron. Sie nutzt den Webview des Systems statt eines
mitgelieferten Chromium. Die Oberfläche ist dieselbe wie in 1.0.0 und im Browser.

| System | Datei | Größe (1.0.0) |
|---|---|---|
| Windows | `forge-dsp-1.1.0-win-x64-setup.exe` (Installer), `…-win-x64.msi`, `…-win-x64-portable.exe` | ~2–4 MB (105–115 MB) |
| macOS (Intel und Apple Silicon) | `forge-dsp-1.1.0-mac-universal.dmg`; unsigniert, beim ersten Start Rechtsklick › Öffnen | ~5 MB (212 MB) |
| Linux, Paket | `…-linux-amd64.deb`, `…-linux-x86_64.rpm` (brauchen WebKitGTK 4.1 aus der Distribution) | ~2 MB |
| Linux, Flatpak | `…-linux-x86_64.flatpak` (`flatpak install --user <Datei>`, holt die GNOME-Runtime von Flathub) | ~2 MB |
| Linux, ohne Installation | `…-linux-x86_64.AppImage` (bringt WebKitGTK mit) | ~78 MB (119 MB) |

Windows braucht WebView2, das in Windows 10 und 11 enthalten ist.

## Neu

- **Anschlusswahl:** eigenes Fenster statt des Browser-Dialogs. Es zeigt nur USB-Anschlüsse, der Forge (CP2102) zuerst;
  ist genau ein Forge angeschlossen, verbindet die App ohne Rückfrage. Andere serielle Anschlüsse hinter „alle
  Anschlüsse zeigen“.
- Serielle Verbindung, „Speichern unter“ und der Abruf der Firmware-Releases laufen über die App selbst (Rust),
  Firmware mit Prüfung der SHA-256 aus GitHub.

## Bekannte Einschränkungen

- Geprüft: Start und Oberfläche unter Linux. Windows und macOS sind gebaut, aber noch nicht am Gerät getestet.
- Mehrere Forge in einer Kette (RS485) bedient die Oberfläche noch nicht (#15).
